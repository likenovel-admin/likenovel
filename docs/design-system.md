- 기본: `rounded-lg` (8px)

- 작품 상세의 데스크톱 CTA는 태그 수와 무관하게 별도 행에서 오른쪽 정렬하며, 모바일은 채팅과 첫회/이어보기 CTA의 2열 배치를 유지한다.

#### 구분선
- 얇은: `border-light-gray-500`
- 블록: `bg-light-gray-100 h-[20px]`

#### 홈 랭킹 구좌 헤더
- `인기 무료 Top`과 `유료 Top` 모바일 헤더는 첫 행에 제목과 `더보기`, 둘째 행에 랭킹 기준 시각과 안내 아이콘을 둔다.
- 제목과 `더보기`는 320~375px에서도 줄바꿈하지 않으며, `md` 이상에서는 기존 한 행 배치로 복귀한다.
- 모든 홈 구좌의 `더보기`는 모바일 13px, `md` 이상 14px로 표시하고 축소·줄바꿈하지 않는다.

#### 작품 목록 카드
- 일반 작품 목록은 연재 정보와 태그 사이에 작품소개를 모바일 12px, 데스크톱 14px의 보조색으로 최대 2줄 노출한다. 빈 소개글과 작가 관리 목록은 이 영역을 숨기며, AI 사서 브리핑은 기존 별도 영역을 유지한다.
- 모바일의 통계와 선호작 액션은 카드 우상단 상태 배지 행에 인플로우로 배치해 제목과 작품소개 영역을 침범하지 않는다.

#### 그림자
- 스티키 헤더: `shadow-[0px_6px_10px_0px_rgba(0,0,0,0.06)]`
- 모달: `shadow-xl`

### 1.7 캐릭터챗 메시지 상태

- 작품 상세의 `주인공챗` 섹션은 표지 영역과 AI 사서 사이에 표시하며, 홈 메뉴·홈 구좌·웹소챗 시작 화면과 동일하게 `주인공챗` 명칭을 쓰고 `등장인물과 바로 대화해요` 서브카피로 기능을 설명한다. 현재 작품에서 대화 가능한 캐릭터가 있을 때만 노출하고, `읽은 회차까지만 기억해요` 안내와 함께 PC 2열·모바일 가로 스크롤 카드로 제공한다. 카드에는 인물 대사(말투 샘플)를 두 줄까지 보여주고, 인물 이미지가 없으면 기본 표지 대신 이름 첫 글자 자리표시자를 쓴다. 카드나 인물 이미지를 누르면 기존 캐릭터 미리보기 모달(장면 발췌·회차 선택)을 열고, `대화하기` 버튼은 읽은 회차 기반 스포일러 경계를 그대로 적용해 모달 없이 바로 채팅을 시작한다. 이어지는 AI 사서는 운영 화면과 동일하게 유지한다.
- 메인 캐릭터 구좌는 `다음 회차를 기다리는 동안, 주인공챗` 제목 아래 읽은 범위·스포일러 차단·새 장면 전개를 설명하는 서브카피 6종 중 하나를 진입 시 노출한다.
- 홈 캐릭터 카드를 누르면 모바일은 bottom sheet, 데스크톱은 modal을 열어 대화를 시작하거나 작품 상세로 이동한다. `대화하기`를 누르면 채팅 화면을 먼저 연 뒤 기존처럼 세션을 생성한다.
- 웹소챗과 캐릭터챗은 PC·모바일 모두 52px 공통 헤더를 사용한다. 뒤로가기는 진입 직전의 내부 경로로 복귀하고, 해당 경로가 없으면 현재 작품 상세 또는 홈으로 이동한다. 일반 화면 이탈은 마지막 활성 세션을 보존하며, 활성 세션은 새 대화·새 캐릭터 진입이나 PC·모바일 상단 내비바의 `웹소챗` 진입처럼 `웹소챗`·`주인공챗` 선택 화면으로 전환할 때만 초기화하되 서버 세션은 삭제하지 않는다. 내비바 진입은 로그인 여부와 기존 세션 유무에 관계없이 적용하며, 이미 웹소챗에 있어도 동일하다.
- 첫 인사 생성·조회 중에는 캐릭터 아바타 옆 assistant 말풍선을 즉시 만들고 3점 입력 표시를 보여준다.
- 신규 진입의 첫 인사는 저장된 완성본을 1회만 점진 표시한다. 기존 세션 재진입에서는 과거 메시지를 즉시 표시한다.
- 세션 생성 응답이 유실되면 방금 생성된 동일 캐릭터 세션을 먼저 복구하고, 첫 인사 조회가 실패하면 잠금을 풀어 `다시 불러오기`를 제공한다.
- 이후 답변은 SSE delta를 같은 assistant 말풍선에 이어 붙인다. 캐릭터챗은 큰 delta도 표시 버퍼에서 점진 노출하며, 첫 delta 전에는 동일한 3점 입력 표시를 사용한다.
- 서버 응답 완료 후 표시 버퍼를 비우는 동안에는 중단 버튼을 노출하지 않는다.
- 캐릭터챗 세션은 RP 전용이므로 입력창에서 모드 선택기를 노출하지 않는다. 같은 위치에는 요술봉 선택지 버튼을 두고, 켜진 동안 최신 캐릭터 답변 뒤에 사용자 선택지 3개를 표시한다. 빈 새 대화는 `웹소챗`과 `주인공챗`을 먼저 선택하게 하며, 선택 전에는 작품 정보 영역과 입력창을 숨긴다. `웹소챗`은 기존 작품 선택기를 열고, `주인공챗`은 공개 API가 반환한 대화 가능 캐릭터만 2/4/6열로 보여준 뒤 기존 미리보기 모달에서 시작한다. 일반 웹소챗의 모드 선택 UI와 응답 액션에는 `인물과 대화`를 노출하지 않으며, 기존 RP 세션과 자연어 요청 처리는 유지한다.
- 주인공챗 선택 카드에는 이미지, 작품명, 캐릭터명, `~N화까지`와 역할 배지만 표시한다. 역할 배지는 이미지 좌하단에 같은 크기·간격·모서리로 배치하고, `주인공`은 `primary-100` 배경과 흰 글자, `주요인물`은 반투명 흰 배경과 `primary-100` 글자·테두리를 사용한다. `양호`, `보통`, `부족`, readiness, 점수, 퍼센트 같은 CMS 운영 상태는 유저웹에 노출하지 않는다.
- 캐릭터챗 입력 힌트는 무료 잔여 횟수가 있으면 `무료 N회 채팅 가능`을 표시한다. 무료 횟수를 모두 사용하면 첫 번째 선택지 대사를 사용하고, 선택지가 없으면 중립적인 입력 안내를 표시한다.
- 모델 선택기는 캐릭터챗 입력창 맨 왼쪽에만 둔다. 데스크톱은 입력창 위 popover, 모바일은 키보드를 내린 뒤 bottom sheet로 열며, 모델명·메시지당 캐시·무료 잔여 횟수는 백엔드 `modelOptions`를 SSOT로 사용한다. 선택은 캐릭터챗 세션에 저장하고 생성·저장 중에는 변경을 막는다.
- 일반 웹소챗은 모델 선택기를 노출하지 않고 기존 하루 무료 3회를 유지한다. 캐릭터챗은 스피드 10회·밸런스 5회·딥 1회를 모델별로 제공한다. 다음 회차 생성은 스피드 경로·30C로 고정하며, 첫 안내·선택지 등 정적 응답은 과금하지 않는다.
- 메인 캐릭터 구좌의 CMS 작품 후보는 공개 회차가 15화 이상이고 플랫폼 내 AI 콘텐츠 서비스에 동의한 공개 작품으로 제한한다. 기존 수집 cohort 기준일은 유지하며, 해당 작품의 `character_inventory_v3`에서 공개 채팅·구좌 적격과 표시 안전 조건을 모두 통과한 주·조연만 관리자가 선택한다.
- 메인 캐릭터 구좌는 CMS 전체 공개 목록 중 현재 공개 조건을 통과한 `card_order` 상위 12명을 사용한다. 데스크톱은 6열 2행으로 전체를 노출해 페이지 이동을 숨기고, 태블릿은 4열 2행, 모바일은 2열 2행 단위로 좌우 순환한다. 임의 셔플은 하지 않는다.
- 홈 구좌 우상단의 기존 `더보기`로만 `/product/character-chat` 전체 목록에 진입한다. 별도 GNB·메뉴 진입점은 추가하지 않는다.
- 전체 목록은 `max-w-[1120px]` 안에서 모바일 16px, 태블릿 24px, 데스크톱 32px 좌우 여백을 항상 유지한다. 카드 격자는 모바일 2열, 태블릿 4열, 작은 데스크톱 5열, 넓은 데스크톱 6열을 상한으로 하며 카드 비율은 364:414를 유지한다.
- 전체 목록 상단은 작품 범위 `전체 / 읽고 있는 작품`, 역할 `모든 캐릭터 / 주인공 / 주요인물`, 정렬 `추천순 / 등록순`을 별도 제어한다. 데스크톱은 작품 범위를 왼쪽 버튼으로 두고 역할 select를 정렬 select 바로 왼쪽에 묶는다. 모바일은 작품 범위 select를 첫 줄에 두고, 둘째 줄에 역할 select와 정렬 select를 같은 순서로 붙인다.
- 전체 목록의 `추천순`은 `fullReady` → `chatQuality` → 공개 회차요약 coverage → 캐릭터가 등장한 고유 회차 수 → RP 예시 수 → 장면 수 → 역할(주인공 우선) → stable character ID 순으로 정렬한다. 역할은 앞선 품질 지표가 모두 같은 경우에만 tie-break로 사용하고, 동일한 `fullReady`·`chatQuality` 구간에서는 같은 작품의 두 카드가 연속되지 않도록 다른 작품 카드를 사이에 배치한다. readiness·품질 점수·퍼센트는 정렬에만 사용하고 유저 UI에는 노출하지 않는다.
- 홈은 CMS에서 현재 활성화한 구좌의 `card_order` 상위 12명을 노출하고, `더보기` 전체 목록은 공개·비블라인드·AI 콘텐츠 서비스 동의·공개 15화 이상 작품 중 `public_chat_eligible` 캐릭터에 유효한 RP 프로필, 어느 회차든 비어 있지 않은 RP 예시, 활성 회차요약, 캐릭터 키가 일치하는 사용 가능 장면이 있는 행을 자동 후보로 삼는다. 공개 응답의 역할은 `work_role=main_protagonist`(또는 legacy `is_protagonist=true`)를 `main_protagonist`, `work_role=major_character`를 `major_character`로만 정규화하고 그 외 값은 주요인물로 추정하지 않고 제외한다. 후보는 작품·canonical character key 기준으로 중복 제거하고 작품당 최대 2명까지 주인공 우선으로 노출하며, 이미지는 캐릭터 이미지 → 작품 표지 → 기본 이미지 순으로 대체한다. 자동 후보의 `entryEpisodeNo`는 가격과 회차 제목을 해석하지 않고 해당 캐릭터가 실제 등장하는 사용 가능 장면 중 가장 이른 양의 `episode_no`로 계산하며, 연속 준비 범위 안에 있을 때만 노출한다. 전체 목록에는 수집 기준일·연재상태·`public_slot_eligible`·1화 고정 장면·RP 예시 0~1화 제한을 hard gate로 사용하지 않는다. 모달 회차 선택은 `entryEpisodeNo`부터 `min(읽은 회차, 연속 준비 회차)`까지만 제공하고 읽은 기록이 그보다 앞서거나 없으면 `entryEpisodeNo`를 기본으로 사용한다. 기존 CMS 홈 슬롯은 K 보조 조회 실패로 숨기지 않고 1화를 기본값으로 유지하며, 기존 세션의 저장·재진입에는 새 자동 노출 gate를 소급하지 않는다. 세션 장면은 선택한 캐릭터와 정확히 일치하는 읽은 범위 내 장면을 우선하고, 없으면 같은 읽은 범위의 실제 작품 장면에 IF 방식으로 합류하되 미래 회차는 사용하지 않는다.
- CMS 캐릭터챗 노출 관리는 `메인 12명 편성`, `전체 공개`, `후보 검수`를 분리한다. 후보 검수에는 캐릭터별 회차 수, RP 예시 수, 장면 수와 품질 사유를 표시하고 품질 미달 캐릭터의 등록·수정은 서버와 UI 양쪽에서 막는다.
- `prefers-reduced-motion: reduce`에서는 첫 인사와 후속 답변의 점진 표시를 생략한다.
- 캐릭터챗 assistant 본문은 빈 문단 기준으로 지문과 대사를 분리한다. 지문은 아바타와 말풍선 없이 대사 텍스트 시작선에 맞추고, 대사는 캐릭터명·32px 원형 프로필·`light-gray-100` 말풍선으로 표시한다.
- 카드와 진입 모달은 CMS에서 크롭한 동일 `characterImagePath`를 364:414 구도로 사용하고, 선택 주인공의 채팅 대사는 같은 이미지를 32px 원형 아바타로 표시한다. 화자가 명시된 다른 인물 대사는 기본 원형 프로필을 사용하며, 캐릭터명은 모든 대사 말풍선 위에 표시한다.
- 화자를 안전하게 분류할 수 없는 assistant 텍스트는 주인공 발화로 강제하지 않고 지문으로 표시한다. user 말풍선은 `primary-100`을 사용하고 모바일 본문은 16px 이상을 유지한다.

## 6. 절대 하지 말 것

### 유저웹 (service)
1. `max-w-[1120px]` 대신 다른 값 사용 금지
2. Pretendard 외 폰트 사용 금지 (뷰어 제외)
3. `letter-spacing` 값 `-2%` 외 사용 금지
4. 새 색상 토큰 추가 금지 — 기존 팔레트에서 가장 가까운 값 사용
5. 데스크톱에서 `px-16pxr` 남겨두기 금지 — `md:px-0`
6. border-radius 임의값 금지 — 6/8/10/20/100px 중 선택
7. 모바일에서 카드 border 넣기 금지 — `md:border` 조건부만

### partner/cms 공통
1. shadcn/ui 토큰 무시하고 하드코딩 금지 — `bg-background`, `text-foreground` 등 사용
2. 사이드바 너비 224px 변경 금지
3. 테이블 행 높이 91px 기준 변경 금지
4. 페이지네이션 패턴 변경 금지 (6px-6px-20px-20px radius)
5. 모달은 반드시 rounded-[20px] + 적절한 shadow
6. partner Figma에 없는 색상 임의 추가 금지 — Figma 팔레트 내에서 선택
7. 기존 shadcn/ui 컴포넌트가 있으면 직접 구현 금지 — 기존 것 사용

### 전체
1. 앱 간 디자인 시스템 혼용 금지 (service 색상 토큰을 partner에서 쓰거나 그 반대)
2. Figma 미확인 상태로 신규 페이지 디자인 금지 — 반드시 해당 섹션 노드 조회
3. Figma 와이어프레임(CMS)의 색상을 그대로 프로덕션에 쓰기 금지
