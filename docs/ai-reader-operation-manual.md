# AI 독자 운영 메뉴얼

이 문서는 CMS `AI 유저 인게이지먼트` 화면에서 AI 독자를 운영하는 실무 기준입니다.

핵심 사이클은 아래 순서입니다.

1. 설정을 조정한다.
2. 운영을 시작하거나 다시 시작한다.
3. 최근 반영 활동과 독자 로그를 본다.
4. 필요하면 운영을 멈춘다.
5. 다음 실험 설정으로 다시 시작한다.

## 화면 구역

### 기간 조회

상단 날짜 필터는 운영 기간을 정하는 곳이 아니라, 대시보드에서 볼 통계 기간을 정하는 곳입니다.

- `기간 적용`: 선택한 날짜 범위로 KPI, 최근 활동, 작품별 효과를 다시 조회합니다.
- `새로고침`: 현재 조건으로 최신 데이터를 다시 불러옵니다.

운영 스케줄 기간은 아래 `AI 독자 운영 > 운영 설정`에서 정합니다.

### 상태 지표

상단 KPI는 현재 운영 상태를 빠르게 보는 영역입니다.

- `활성 AI`: active 상태인 AI 독자 수입니다.
- `스케줄 있음`: 남은 운영 스케줄이 있는 active AI입니다.
- `할 일 없음`: active지만 남은 스케줄이 없는 AI입니다.
- `투입 가능`: 지금 다시 시작할 수 있는 eligible idle active AI입니다.
- `선택 기간 스케줄`: 조회 기간 안의 스케줄 수입니다.
- `실패 스케줄`: 스케줄 처리 실패 수입니다.
- `LLM 성공률`: LLM 판단 성공 비율입니다.

## 기본 운영 사이클

### 1. 목표 인원 정하기

`목표 활동 인원`에 이번 실험에서 돌릴 AI 독자 수를 입력합니다.

- 빠른 버튼: `0명`, `50명`, `100명`, `500명`, `1000명`
- 직접 입력: 1~1000명
- `0명`은 전체 정지 목적일 때만 사용합니다.

### 2. 운영 설정 정하기

`운영 설정`에서 이번 실험의 기간과 시작 방식을 정합니다.

- 기간: `오늘만`, `3일`, `7일`, `14일`, `30일`, `90일`, 직접 입력
- 시작 방식:
  - `바로 시작`: 지금부터 즉시 배치를 생성합니다. 500명 이상은 최대 100명 단위로 나누어 시작합니다.
  - `예약 시간부터 시작`: 즉시 배치 없이 설정한 날짜와 활동 시간에 맞춰 스케줄만 생성합니다.
- `상세 설정 보기`: 강도, 활동 시간, 세션 목표, LLM 예산, 작품 가중치, 무료연재 내부 비중, 연재 상태 가중치, 연령/성별 비율, 프리셋을 조정합니다.
- 활동 시간의 `연령별 생활패턴`은 각 AI 독자에 저장된 연령대에 맞춰 활동 시간을 자동 분산합니다. 작품 가중치, 강도, 인원, 저장된 연령대는 바꾸지 않습니다.
- `연령별 생활패턴` 적용 후 시간표를 직접 수정하면 기존 공통 시간표 방식으로 돌아갑니다.
- `작품 가중치` 탭: AI 독자가 새 작품을 고를 때 `무료연재`와 `유료연재` 후보 중 어느 쪽을 우선 볼지 비율로 조정합니다. 기본값은 `무료연재 100 / 유료연재 0`이고, 합계는 100이어야 합니다. 무료연재 안에서는 기본값 `일반연재 85 / 자유연재 15`를 사용합니다.
- `연재 상태 가중치`: 기본 `전체`는 기존처럼 연재상태를 보지 않습니다. `연재중 중심`이나 `연재중만`을 고르면 `연재중` 작품을 더 우선합니다.
- 작품 가중치는 새 작품 후보군을 정합니다. 한 작품을 3화 이상 읽은 AI 독자는 성향에 따라 35~55%의 세션에서 새 작품을 탐색합니다. 새 후보는 최근 7일 AI 조회가 많을수록 선택 점수를 완만하게 낮추고, 취향 점수 상위 50~100% 범위에서 독자별로 분산 선택합니다.
- 동적 배분은 읽기 기회를 순환시키는 정책입니다. 추천·선호작·평가는 기존 LLM 판단과 일일 상한을 그대로 적용하므로 작품별 긍정 반응을 강제로 맞추지 않습니다.

기간은 실험 변수입니다. 1일만 고정해서 보지 말고, 작품/목표에 따라 3일, 7일, 14일 이상도 사용합니다.

### 3. 다음 작업 누르기

`다음 작업` 박스가 현재 상태를 보고 눌러야 할 버튼을 하나로 정리합니다.

| 화면 상태 | 주 버튼 | 의미 |
| --- | --- | --- |
| 시작 가능 | `운영 시작` | 멈춰 있는 AI를 켜고 현재 설정으로 운영을 시작합니다. |
| 운영 종료됨 | `운영 다시 시작` | 스케줄이 끝난 active AI를 현재 설정으로 다시 시작합니다. |
| 운영 중 | `기존 예약 교체 후 시작` | 남은 예약과 대기 액션을 현재 설정으로 교체합니다. |
| AI 부족 | `신규 AI 독자 생성 열기` | 목표 인원을 채우기 위해 신규 AI 생성 영역을 엽니다. |
| 목표 오류 | `목표 인원 확인 필요` | 목표 인원 값을 먼저 수정해야 합니다. |

운영자는 보통 이 버튼 하나만 보면 됩니다.

## 운영 케이스별 사용법

### 케이스 A. 처음 운영을 시작할 때

1. `목표 활동 인원`을 정합니다.
2. `운영 설정`에서 기간과 시작 방식을 정합니다.
3. 필요하면 `상세 설정 보기`에서 강도, 활동 시간, 작품 가중치를 조정합니다.
4. `다음 작업`의 `운영 시작`을 누릅니다.
5. 실행 후 `최근 반영 활동`과 `독자 로그 보기`에서 반응을 확인합니다.

### 케이스 B. 운영 기간이 끝난 뒤 같은 설정으로 다시 돌릴 때

이 경우 active AI는 남아 있지만 남은 스케줄이 없습니다.

1. `할 일 없음` 수와 `투입 가능` 수를 확인합니다.
2. 목표 인원이 현재 active 수와 같다면 그대로 둡니다.
3. 기간을 새로 정합니다. 예: 3일, 7일, 14일.
4. `다음 작업`의 `운영 다시 시작`을 누릅니다.
5. 로그를 보며 반응을 확인합니다.

### 케이스 C. 설정을 바꿔서 다시 실험할 때

예: 연령 비율, 작품 가중치, 연재 상태 가중치, 활동 시간, 강도, 기간을 바꾸고 다시 돌리는 경우입니다.

1. `상세 설정 보기`를 엽니다.
2. 프리셋, 강도, 세션 목표, LLM 예산, 작품 가중치, 연재 상태 가중치, 활동 시간, 연령/성별 비율을 조정합니다. 연령대별 시간 분산만 바꾸려면 활동 시간의 `연령별 생활패턴`을 선택합니다.
3. 기간과 시작 방식을 다시 확인합니다.
4. 이미 운영 중이면 `다음 작업`에 `기존 예약 교체 후 시작`이 표시됩니다.
5. 버튼을 누르면 확인창이 뜹니다.
6. 확인하면 남은 예약과 대기 액션을 현재 설정으로 교체하고 다시 시작합니다.

주의: `기존 예약 교체 후 시작`은 남은 예약과 대기 액션을 바꿉니다. 이미 반영된 로그와 지표는 삭제하지 않습니다.

### 케이스 D. 운영 중 잠깐 멈출 때

1. 우측 `운영 멈추기`를 누릅니다.
2. 확인창 내용을 읽고 진행합니다.
3. 진행하면 활동 중인 AI를 일시정지하고 남은 스케줄/action 대기열을 정리합니다.

멈추기는 계정, 과거 로그, 이미 반영된 지표를 삭제하지 않습니다.

### 케이스 E. AI가 부족할 때

`다음 작업`에 `신규 AI 독자 생성 열기`가 보이거나, 목표 인원 안내에 부족분이 표시됩니다.

1. `상세 설정 보기`를 엽니다.
2. 하단 `신규 AI 독자 생성` 영역으로 갑니다.
3. prefix, 신규 AI 독자 수, 날짜, 세션 목표, LLM 예산을 확인합니다.
4. `1. 사전 확인`을 누릅니다.
5. 사용 가능/부족 수와 기간을 확인합니다.
6. `2. 투입 적용`을 누릅니다.
7. 부족한 AI 전용 계정이 있으면 같은 버튼에서 부족분을 자동 발급한 뒤 AI 독자 등록과 스케줄 생성을 이어서 처리합니다.

사전 확인 없이 바로 적용할 수 없습니다.

### 케이스 F. 로그를 보고 판단할 때

운영 후에는 상단 버튼보다 아래 모니터링 영역을 봅니다.

- `최근 반영 활동`: 실제 반영된 최근 활동 30건입니다.
- 활동 행 클릭: 해당 AI 독자 상세로 이동합니다.
- `독자 로그 보기`: 전체 로그 화면으로 이동합니다.
- `시간대 활동`: 어느 시간대에 활동이 몰렸는지 봅니다.
- `작품별 AI 활동 효과`: 작품별 조회, 선호작, 추천, 평가 효과를 비교합니다.
- `선택 범위 반응`: 조회 기간 기준 KPI를 봅니다.

## 자주 쓰는 운영 패턴

### 짧은 테스트

- 목표: 10~50명
- 기간: 오늘만 또는 3일
- 시작: 바로 시작
- 목적: 설정이 정상적으로 반응하는지 빠르게 확인

### 일반 실험

- 목표: 50~500명
- 기간: 3일 또는 7일
- 시작: 바로 시작 또는 예약 시간부터 시작
- 목적: 작품별 반응 차이와 시간대별 반응 확인

### 장기 운영

- 목표: 500명까지. 1000명은 500명 운영 지표를 확인한 뒤 단계적으로 사용합니다.
- 기간: 14일, 30일, 90일
- 시작: 예약 시간부터 시작 권장
- 목적: 안정적인 장기 반응 누적

## 버튼 판단 기준

| 버튼 | 언제 쓰나 | 주의 |
| --- | --- | --- |
| `운영 시작` | 멈춰 있는 AI를 현재 설정으로 새로 시작할 때 | 목표 인원과 기간을 먼저 확인합니다. |
| `운영 다시 시작` | 운영이 끝난 active AI를 다시 돌릴 때 | 같은 인원이라도 기간/시작 방식을 새로 확인합니다. |
| `기존 예약 교체 후 시작` | 운영 중 설정을 바꿔 반영할 때 | 남은 예약과 대기 액션이 교체됩니다. |
| `운영 멈추기` | 운영을 중단할 때 | confirm 후 남은 스케줄/action 대기열이 정리됩니다. |
| `상세 설정 보기` | 강도, 시간, 작품/연재상태 가중치, 비율, 프리셋을 바꿀 때 | 설정만 바꾸는 버튼입니다. 실행은 `다음 작업`에서 합니다. |
| `독자 로그 보기` | 실제 활동 로그를 확인할 때 | 아래 `최근 반영 활동` 영역에서 사용합니다. |
| `신규 AI 독자 생성` | 목표 인원 대비 AI가 부족할 때 | 먼저 사전 확인을 통과해야 합니다. |

## 실수 방지 체크리스트

운영 버튼을 누르기 전 아래 항목을 확인합니다.

- 목표 활동 인원이 맞는가?
- 기간이 이번 실험 의도와 맞는가?
- 작품 가중치 합계가 100인가?
- 무료연재 내부 비중 합계가 100인가?
- 연재 상태 가중치를 켰다면 합계가 100인가?
- `바로 시작`과 `예약 시간부터 시작` 중 올바른 시작 방식을 골랐는가?
- 운영 중이라면 `기존 예약 교체 후 시작`이 맞는 상황인가?
- 로그 확인은 아래 `최근 반영 활동` 또는 `독자 로그 보기`에서 할 준비가 됐는가?

## 장애나 이상 상황

### 버튼이 비활성화됨

- 다른 작업이 진행 중일 수 있습니다.
- 새로고침 후 다시 확인합니다.
- 목표 인원이 1~1000 범위인지 확인합니다.

### 운영 다시 시작이 안 됨

- `투입 가능` 수가 0인지 확인합니다.
- excluded 안내가 있으면 계정 상태, 도메인, SNS 조건을 확인해야 합니다.

### 신규 AI가 부족함

- `신규 AI 독자 생성`에서 사전 확인을 먼저 실행합니다.
- 부족 수가 표시되면 `투입 적용` 시 부족한 AI 전용 계정이 자동 발급됩니다.
- 자동 발급 후에도 부족하다고 나오면 email prefix, 허용 도메인 설정, Keycloak/DB 계정 생성 실패를 확인합니다.

### 실패 스케줄이 증가함

- `실패 스케줄` KPI를 확인합니다.
- `독자 로그 보기`에서 실패/미반영 내역을 확인합니다.
- 같은 설정으로 반복 실행하지 말고 원인을 먼저 확인합니다.

## AI 독자 댓글 정책

2026-09-08 합의 기준이며 같은 날 DEV·PROD에 배포했습니다. 공개 댓글 화면에서
실제 등록 결과를 확인하는 단계는 아직 남아 있습니다.

- 독자·작품 조합의 고정 해시로 꾸준히 남기는 독자 10%, 가끔 남기는 독자 90%를
  확률 배정합니다. 실제 유한한 독자 집합의 인원 비율은 변동하며, 같은 작품을 읽는
  동안 구분은 유지됩니다. 별도 성향 모델이나 댓글용 LLM 호출은 없습니다.
- 꾸준한 독자는 첫 읽기에서 후보가 되고 이후 새로 읽은 회차는 80% 확률로 후보가
  됩니다. 가끔 남기는 독자는 회차 구간에 따라 1~25화 1%, 26~50화 0.4%,
  51화 이상 0.15%입니다. 실제 사람 댓글이 초반 회차에 집중되기 때문에, 조용한
  독자가 뒷부분 회차에만 불쑥 남기지 않도록 뒤로 갈수록 확률을 낮춥니다. 꾸준한
  독자는 이 감쇠를 적용하지 않고 읽는 회차를 계속 따라갑니다. 후보가 됐다는 사실은
  등록 보장이 아니며 아래 등록 가드를 통과해야 합니다.
- 꾸준한 독자의 문구는 작품별로 고정된 `잘 봤습니다.`, `잘 보고 갑니다.`,
  `잘 읽었습니다.`, `건필하세요.`, `응원합니다.`, `감사합니다.` 중 하나입니다.
  가끔 남기는 독자는 위 인사와 기존 `재밌네요.`, `다음화 기대됩니다.`,
  `술술 읽히네요.`, `느낌 좋네요.`, `계속 볼게요.` 중 하나를 선택합니다.
- 댓글은 실제 새 읽기 저장과 같은 transaction에서 기존 action queue에 예약합니다.
  기존 독서 이력을 되감거나 과거 회차 댓글을 소급 생성하지 않습니다. 같은
  독자·작품·회차는 재독·재시도·삭제 뒤에도 다시 댓글을 생성하지 않습니다.
- 독자·작품별 지연은 10분~6시간 범위에서 고정해 해당 독자의 읽기 순서를 유지합니다.
  다음 날로 넘어갈 수 있으며 자정 직전으로 시간을 잘라 몰아넣지 않습니다.
- 같은 회차의 AI 댓글은 최근 24시간 최대 3개이고, 직전 AI 댓글과 최소 30분 간격을
  둡니다. 삭제·숨김 처리한 AI 댓글도 이 한도에는 포함합니다. 기존 작품 하루 2개와
  회차 하루 1개 제한은 이 정책으로 대체하며, 별도 전체 일일 총량 제한은 없습니다.
- 회차 조회수가 20 미만이면 등록하지 않고 `comment_view_count_too_low`로 건너뜁니다.
  조회수가 거의 없는 회차의 댓글은 독자 눈에 인위적으로 보이기 때문입니다.
- 실제 등록 시 공개·활성·무료 열람 대상·댓글 허용·읽기 이력·하차 여부를 재확인합니다.
  완결 작품의 마지막 공개 회차에는 `다음화 기대됩니다.`와 `계속 볼게요.`를 등록하지
  않습니다. 일반 댓글 API의 작가 알림·이벤트 리워드는 실행하지 않습니다.
- 같은 회차의 모든 공개 댓글을 최신순으로 비교합니다. 위 인사 6종은 같은 문구 2개
  연속까지 허용하고 세 번째는 건너뜁니다. 나머지는 바로 앞과 같으면 건너뜁니다.
- 한도·간격·반복 제한과 잠금 경합은 건너뛰며, 등록 예정 시각을 5분 넘긴 댓글은
  만료시킵니다. 놓친 댓글을 이후에 몰아서 등록하지 않습니다. 워커 로그/queue의
  `comment_24h_limit`, `comment_interval_limit`, `comment_repeated`, `comment_lock_busy`,
  `comment_expired` 사유를 구분합니다.
- 회차 행 잠금은 바깥 transaction의 commit까지 유지합니다. 테스트의 가짜 DB 경계
  검증과 실제 MySQL 동시성 검증을 구분하며, 공개 API/UI에서 댓글·닉네임·시간을
  확인하기 전에는 실제 서비스 패턴이 검증됐다고 보고하지 않습니다.
- 일반 댓글 삭제도 댓글 변경 전에 회차를 먼저 잠가 AI 등록과 잠금 순서를 맞춥니다.
  만료 여부는 초기 검사뿐 아니라 최종 `INSERT ... SELECT`에서도 기존 queue의
  예정 시각으로 판정합니다. 최종 등록 시점 300초는 허용하고 301초는 건너뜁니다.

### 일정·크레딧·워커 중단 시

- 댓글 전용 계정/스케줄이 아니라 기존 AI 독자의 새 읽기가 댓글 후보를 만듭니다.
- 크레딧 보호에 걸리면 새 LLM 세션 판단을 잠시 중단하지만 워커는 기존 대기 액션을
  계속 처리합니다. 이미 예약된 읽기가 실행되면 댓글 후보가 생길 수도 있습니다.
  댓글 선택·등록에는 추가 모델 호출이 없습니다.
- 하루 활동 구간 종료와 독자 운영 기간 만료를 구분합니다. 활성 독자의 기존 액션은
  구간 이후에도 처리할 수 있으나, `auto_pause_after`가 지나 독자가 `paused`로
  바뀌면 만료 정리에서 대기 액션을 취소합니다.
- 워커가 종료되면 새 읽기·댓글 등록 모두 멈춥니다. 복구 시 댓글은 기존 예정 시각의
  5분 유효기간을 유지하며 오래된 댓글을 소급 등록하지 않습니다.
- 세션 판단 중 DB 연결이 무효화된 경우, 실패 기록 전에 기존 transaction을
  rollback하여 `PendingRollbackError`가 다음 댓글 큐 조회까지 전파되지 않게 합니다.
  실제 MySQL 연결 무효화 테스트에서 수정 전 워커 종료를 재현했고, 수정 후 실패
  스케줄 저장과 같은 사이클의 댓글 액션 처리까지 검증했습니다. 영구 DB 장애의
  자동 복구나 운영 재시작 검증을 의미하지 않습니다.

구현 기준은 backend `app/services/ai/reader_agent_comment_policy.py` 및
`reader_agent_action_service.py`입니다. 되돌릴 때는 이번 댓글 변경만 되돌려
배포하며, 이미 등록한 댓글은 별도 승인 없이 일괄 삭제하지 않습니다.
